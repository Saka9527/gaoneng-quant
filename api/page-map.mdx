## 1. 数量

| 范围 | 个数 | 说明 |

| 回测服务 JSON 接口（8080） | **22** | 下面第 2～3 节全部路径 |
| 其中产品页直接调用 | **9** | 页面发起的请求 |
| 已开放、页面未调用 | **13** | 运维和备用查询。`/portfolio/submit` 仍在，但页面不再调用 |

## 2. 回测工作台（`#/backtest`、`#/backtest/result`）

工作台打开时先拉三份配置，点按钮后再调对应接口。

| 页面功能 | 方法 | 路径 | 何时调用 |
|----------|------|------|----------|
| 底池下拉 | GET | `/api/v1/universe` | 进入工作台 |
| 右侧交易模型的枚举和默认值（均线、买入排序、卖出信号、仓位、过滤） | GET | `/api/v1/portfolio/meta` | 进入工作台。14 项买入排序、38 项卖出信号和涨跌停口径见 [组合回测枚举（GET /api/v1/portfolio/meta）](/api/portfolio-meta)。默认卖出 `MA_DEATH`，`excludeSt` 默认 false |
| 左侧因子分组（推荐 / 独家 / 板块） | GET | `/api/v1/product/factors` | 进入工作台、切换一级/二级分类或排序 |
| 预览选股 | POST | `/api/v1/product/factor-combo/preview` | 「预览选股」。只取各因子在 `gn_factor_signal` 里的最新一个信号日，不走选股服务 |
| 保存动态组合 | POST | `/api/v1/product/factor-combo/save` | 「保存动态组合」 |
| 回测 | POST | `/api/v1/portfolio/run` | 结果页在同一次请求里跑完。响应含净值曲线和全部成交，字段见 [组合回测输出结构](/api/portfolio-output) |
| 结果页打开已有任务 | GET | `/api/v1/portfolio/jobs/{jobId}` | 用 `jobId` 重新打开。本进程还留着报告时补净值曲线；成交另拉内存分页 |
| 成交明细翻页 | GET | `/api/v1/portfolio/jobs/{jobId}/trades` | 结果页表格，每页 50 条。成交只在跑任务的那台进程内存里 |
| 保存策略 | POST | `/api/v1/portfolio/strategies` | 工作台「保存策略」。立刻按回看年数回测到今天，写入收益和持仓 |
| 我的策略列表 | GET | `/api/v1/portfolio/strategies` | 「我的策略」。收益摘要，不含曲线 |
| 策略详情 | GET | `/api/v1/portfolio/strategies/{strategyId}` | 配置、净值曲线、期末持仓 |

导出净值 CSV 用的是已经拿到的报告，不再请求接口。

带 `factorCombo` 的回测在服务内部再请求选股服务 `POST /api/v1/constituents`（8081），按回测区间取每日成分。这一步页面上看不到。

## 3. 已开放、页面未调用（回测服务）

| 方法 | 路径 | 用途 |
|------|------|------|
| GET | `/api/v1/health` | 健康检查 |
| POST | `/api/v1/portfolio/submit` | 与 `/run` 一样在当前请求里跑完。页面已改走 `/run` |
| GET | `/api/v1/ths/securities?q=` | 按代码或名称搜证券 |
| GET | `/api/v1/ths/status` | 行情源模式（当前 mirror）和写库是否可用 |
| GET | `/api/v1/cache/stats` | 日 K 的 Caffeine 与 Redis 统计 |
| GET | `/api/v1/universe/{universeId}` | 股票池详情和样例代码 |
| GET | `/api/v1/universe/{universeId}/codes` | 股票池全部代码，可加 `limit` |
| GET | `/api/v1/universe/market-panel` | 已预热的全市场面板状态 |
| POST | `/api/v1/universe/market-warmup` | 把股票池日 K 预热进内存面板 |
| GET | `/api/v1/product/factor-combo` | 当前用户已保存的动态因子组合 |
| POST | `/api/v1/product/factor-combo/refresh-sectors` | 从同花顺刷新板块、行业的当日成分到 `gn_factor_signal` |

## 4. 选股服务（8081，页面不直接调用）

字段和错误码见 [选股服务（8081）](/api/factor-service)。

| 方法 | 路径 | 谁调用 | 作用 |
|------|------|--------|------|
| POST | `/api/v1/constituents` | 回测进程 | 按 `from` / `to` 和因子组合返回每日成分。数据来自本机 `membership.bin` 装进内存后的交并 |
| GET | `/api/v1/membership/status` | 运维 | 快照是否就绪、因子数、行数、日期范围、文件路径 |
| POST | `/api/v1/membership/rebuild` | 运维 | 用 `gn_factor_signal` 重写快照。这会覆盖预热算出来的三年成分。字段说明见 [选股服务（8081）](/api/factor-service) |
