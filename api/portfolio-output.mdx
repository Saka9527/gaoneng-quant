同一笔回测有两份输出。`POST /run` 带净值曲线、期末持仓和全部成交。写入 `bt_job.result_json` 的是摘要，曲线和成交都是空数组。

## 1. `POST /api/v1/portfolio/run` 的 `data`

同步跑完后的完整结果。`trades` 含买入和卖出，按发生顺序排列。

| 字段 | 类型 | 说明 |
|------|------|------|
| `jobId` | string | `pf_` 加 16 位十六进制 |
| `universeId` | string | 股票池 |
| `benchmarkCode` | string | 对比指数 |
| `candidateCount` | int | 实际载入的股票数 |
| `tradingDays` | int | 净值点数，按交易日 |
| `loadMs` / `computeMs` | long | 加载、撮合耗时，毫秒 |
| `initialCash` | double | 初始资金 |
| `finalEquity` | double | 期末权益 |
| `totalReturn` | double | `finalEquity / initialCash - 1` |
| `benchmarkReturn` | double | 对比指数同期收益。指数加载失败时用候选股等权收盘代替 |
| `maxDrawdown` | double | 权益相对历史峰值的最大回撤，正数 |
| `annualizedReturn` | double | `(1 + totalReturn) ^ (252 / 交易日) - 1` |
| `sharpeRatio` | double | (日收益 − 0.02/252) 的均值 / 总体标准差 × √252。有效收益少于 2 段时为 0 |
| `turnover` | double | 各净值日单边换手的平均。单边换手为 0.5 乘以权重绝对变化之和，权重含现金 |
| `tradeCount` | int | 完成的卖出笔数，不含买入 |
| `winTrades` | int | 卖出且 `pnl > 0` 的笔数 |
| `winRate` | double | `winTrades / tradeCount`，`tradeCount` 为 0 时为 0 |
| `holdingPeriodDays` | int | 配置的持股天数 |
| `avgTradeReturn` | double | 卖出 `returnPct` 的平均，没有卖出时为 0 |
| `payoffRatio` | double | 盈利卖出平均收益率 / 亏损卖出平均收益率的绝对值。没有亏损时为 0。与 `profitFactor` 不是同一个数 |
| `maxTradeReturn` / `minTradeReturn` | double | 卖出 `returnPct` 的最大、最小。没有卖出时为 0 |
| `rejectedBuys` / `rejectedSells` | int | 涨跌停或停牌导致未成交的次数 |
| `equityCurve` | array | 见下表 |
| `trades` | array | 全部成交，字段见第 4 节。按发生顺序，`index` 从 1 递增。笔数不少于 `tradeCount`，因为含买入 |
| `holdingsSnapshot` | array | 期末仍持有的仓位 |
| `config` | object | 归一化后的交易配置 |

`equityCurve[]`：

| 字段 | 说明 |
|------|------|
| `date` | `YYYY-MM-DD` |
| `equity` | 当日收盘后权益 |
| `benchmarkEquity` | 对比曲线，起点对齐初始资金 |
| `drawdown` | 当日回撤 |

`holdingsSnapshot[]`：

| 字段 | 说明 |
|------|------|
| `code` | 证券代码 |
| `shares` | 股数 |
| `cost` | 持仓成本金额 |
| `price` | 最后一根 K 线收盘价，缺失为 0 |
| `marketValue` | `shares * price` |
| `holdDays` | 已持有天数 |

## 2. `bt_job.result_json`

成功后都写这份。结果页重开任务时从这里取 `symbol`、`totalReturn`、`barCount`、`candidateCount`。

| 字段 | 说明 |
|------|------|
| `type` | 固定 `PORTFOLIO` |
| `strategyName` | 固定 `PORTFOLIO` |
| `symbol` | 等于 `universeId` |
| `dataSource` | `组合回测·股票池 {universeId}` |
| `barCount` | 等于股票数 `candidateCount`，不是 K 线根数 |
| `candidateCount` | 股票数 |
| `tradingDays` | 交易日数 |
| `tradeCount` | 完成的卖出笔数 |
| `initialCash` / `finalEquity` | 初始资金、期末权益 |
| `totalReturn` / `annualizedReturn` / `maxDrawdown` | 与首屏相同 |
| `sharpeRatio` / `turnover` | 与首屏相同 |
| `winRate` | `winTrades / tradeCount`。分母是完成的卖出笔数，`tradeCount` 为 0 时写 0 |
| `holdingPeriodDays` | 配置的持股天数 |
| `avgTradeReturn` | 卖出收益率平均 |
| `payoffRatio` | 盈亏比：盈利卖出平均收益率 / 亏损卖出平均收益率的绝对值 |
| `maxTradeReturn` / `minTradeReturn` | 卖出收益率的最大、最小 |
| `profitFactor` | 卖出盈利金额合计 / 亏损金额绝对值。没有亏损时写 0 |
| `buyHoldReturn` | 写入的是 `benchmarkReturn` |
| `riskFreeRate` | 固定 `0.02`。Sharpe 计算没有用这个数 |
| `startDate` / `endDate` | 请求里的日期，缺省时可能为空 |
| `loadMs` / `computeMs` | 毫秒 |
| `rejectedBuys` / `rejectedSells` | 拒单次数 |
| `equityCurve` / `priceSeries` / `trades` | 固定空数组 |

## 3. `GET /api/v1/portfolio/jobs/{jobId}`

外层是任务视图，不是报告本身。

| 字段 | 说明 |
|------|------|
| `jobId` | 任务 ID |
| `status` | `PENDING` / `RUNNING` / `SUCCESS` / `FAILED` |
| `clientRequestId` | 当前写的是 `portfolio-ui` |
| `createdAt` / `finishedAt` | epoch 毫秒 |
| `error` | 失败原因 |
| `stage` | 成功为 `DONE`，失败为 `FAILED` |
| `progressPct` | 0–100 |
| `result` | 成功时为上一节的摘要 |

本进程的 `reportCache` 里还有这份报告时，`result.equityCurve` 会被补成完整曲线，并加上 `hasFullReport: true`。进程重启后只剩库里的空曲线。

## 4. `GET /api/v1/portfolio/jobs/{jobId}/trades`

`limit` 默认 50，最大 2000。按成交时间倒序，`offset = 0` 是最新一笔。数据来自本进程内存。

| 字段 | 说明 |
|------|------|
| `jobId` | 任务 ID |
| `total` | 总笔数 |
| `limit` / `offset` | 分页 |
| `hasMore` | 后面是否还有 |
| `trades` | 本页成交 |

`trades[]`：

| 字段 | 说明 |
|------|------|
| `index` | 成交序号，从 1 起，按发生顺序 |
| `code` | 证券代码 |
| `side` | `BUY` / `SELL` |
| `date` | `YYYY-MM-DD`，成交日 |
| `price` | 含成本后的成交价 |
| `shares` | 股数 |
| `amount` | 成交金额 |
| `pnl` | 卖出盈亏。买入为 0 |
| `returnPct` | 卖出收益率。买入为 0 |
| `holdDays` | 卖出时的持有天数。买入为 0 |

内存里没有这份报告时，这一页是空的。进程重启后历史任务的成交不可再翻。
