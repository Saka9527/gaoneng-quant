独立进程 `factor-service`。没有 Swagger。响应是裸 JSON，没有回测服务那层 `{ success, code, message, data, timestamp }`。

浏览器不调用。带回测因子组合时，回测进程的 `FactorConstituentClient` 只调成分接口。

快照文件默认 `factor-service/data/membership.bin`，启动时装入内存。2026-10-14 启动日志：276 个因子，9,267,897 行，79,777 个因子日，2023-09-12 至 2026-10-12。

配置 `quant.membership.rebuild-on-startup` 为 false。不要为了核对文档去调重建接口，重建会用 `gn_factor_signal` 覆盖这份三年快照。

## `POST /api/v1/constituents`

按区间和因子组合做每日成分的交或并。

请求：

| 字段 | 说明 |
|------|------|
| `from` / `to` | `YYYY-MM-DD` |
| `combo.baseUniverseId` | 默认 `all_a` |
| `combo.combineMode` | `INTERSECT` 或 `UNION`，缺省为交集 |
| `combo.factors` | 最多 10 条。每条 `factorId`、`op` |

`op`：`HIT`、`LT`、`GT`、`BETWEEN`、`PERCENTILE`。`HIT` 只看是否入选。其余算子用 `field`（默认 `change_pct`）以及 `min` / `max` 或 `percentileLow` / `percentileHigh`。

响应：`{ "from", "to", "days": [ { "date", "codes": ["000002", ...] } ] }`。

参数不合法返回 400，`{ "error" }`。快照未就绪返回 503，`{ "error" }`。

## `GET /api/v1/membership/status`

| 字段 | 说明 |
|------|------|
| `ready` | 快照是否已装入 |
| `factors` | 因子个数 |
| `rows` | 成分行数 |
| `factorDays` | 因子×交易日个数 |
| `from` / `to` | 快照覆盖区间 |
| `lastBuildMs` | 本次进程内重建耗时；启动加载为 0 |
| `path` | 快照文件路径 |

## `POST /api/v1/membership/rebuild`

无请求体。用库里的 `gn_factor_signal` 重写 `membership.bin` 并重新装入内存，响应字段与 status 相同。页面上的因子预览仍读 `gn_factor_signal` 的最新一个信号日，不读这份快照。
