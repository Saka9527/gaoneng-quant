<p>可以把系统想成一位研究员：先听清问题，再决定去档案室、行情终端还是计算器，最后写一份带来源的说明。下面六类场景经常叠在一起。一个投顾助手往往同时需要知识、实时数据、多步分析和合规控制。</p>\n\n    <div class=\"cards\">\n      <article class=\"card\">\n        <div class=\"k\">场景 1</div>\n        <h3>知识库问答（RAG）</h3>\n        <p>用户问制度、产品说明、研报和内部文档。系统先检索相关段落，再组织成答案。</p>\n        <p class=\"meta-line\">关键能力：解析、切片、向量、混合检索、重排、引用。</p>\n        <p class=\"meta-line\">适合：客服、投研检索、内部助手。</p>\n      </article>\n      <article class=\"card\">\n        <div class=\"k\">场景 2</div>\n        <h3>数据问答（API）</h3>\n        <p>用户用自然语言要数据。系统把它收成受控查询，拿到真实结果后再解释。</p>\n        <p class=\"meta-line\">关键能力：指标口径、查询校验、权限、只读、结果解释。</p>\n        <p class=\"meta-line\">适合：行情、经营分析和财务指标。</p>\n      </article>\n      <article class=\"card\">\n        <div class=\"k\">场景 3</div>\n        <h3>工具调用型问答</h3>\n        <p>模型识别意图，选择行情、财务、选股、回测等工具，再根据工具结果作答。</p>\n        <p class=\"meta-line\">关键能力：工具说明、参数结构、路由、重试、权限和审计。</p>\n        <p class=\"meta-line\">适合：投顾和跨系统查询。</p>\n      </article>\n      <article class=\"card\">\n        <div class=\"k\">场景 4</div>\n        <h3>多步骤分析</h3>\n        <p>一个问题要先取数，再算指标、比较对象，最后形成有数据的结论。</p>\n        <p class=\"meta-line\">关键能力：任务拆解、流程编排、确定性计算、交叉校验。</p>\n        <p class=\"meta-line\">适合：个股诊断、财报和组合分析。</p>\n      </article>\n      <article class=\"card\">\n        <div class=\"k\">场景 5</div>\n        <h3>多轮与个性化</h3>\n        <p>系统要听懂「它」「刚才那只」「继续分析」，并结合用户授权过的偏好。</p>\n        <p class=\"meta-line\">关键能力：对话状态、历史摘要、槽位补全、上下文裁剪。</p>\n        <p class=\"meta-line\">适合：持续投研和复杂咨询。</p>\n      </article>\n      <article class=\"card\">\n        <div class=\"k\">场景 6</div>\n        <h3>可靠性与合规</h3>\n        <p>遇到答不了、数据不够、权限不够或高风险请求时，要拒答或转人工。</p>\n        <p class=\"meta-line\">关键能力：数据校验、规则、风险分级、审计日志、人工复核。</p>\n        <p class=\"meta-line\">适合：金融、医疗、法律和生产系统。</p>\n      </article>\n    </div>\n\n    <div class=\"callout tip\">\n      <svg width=\"16\" <span><b>投顾为什么要组合这几类</b>「这只股票便宜吗」会同时碰到：研报里的观点（知识库）、最新估值（行情工具）、财务口径（指标定义）、和同类的比较（多步分析），以及能不能给买卖建议（合规）。只做一个聊天窗口，覆盖不了这条链路。</span>\n    </div>\n\n  </section>\n\n  <section id=\"s2\">\n    <h2 class=\"sec-title\"><span class=\"num\">02</span>从提示词到 Agent</h2>\n    <p class=\"sec-desc\">能力是一层层加上去的。上一层已经够用时，就不必为了「更先进」跳到下一层。</p>\n    <figure class=\"shot\">\n      <img src=\"/assets/ai-qa/fig-01.png\" alt=\"从提示词工程、检索增强、函数调用到智能体的演进路径\">\n      <figcaption>图：纯文本问答 → 能查外部文档 → 能调外部函数 → 能循环使用多工具、记忆和规划。每一段都是因为上一段不够用才往下走。</figcaption>\n    </figure>\n    <ol class=\"steps\">\n      <li><b>提示词。</b>适合解释概念、改写、总结。实现快，但模型掌握不了你的内部资料，也看不到最新行情。</li>\n      <li><b>RAG。</b>答案必须来自一批文档时使用。重点是找到正确段落，并把出处带回回答，而不只是把整份文档塞进上下文。</li>\n      <li><b>工具调用。</b>答案依赖实时接口或业务计算时使用。模型输出调用请求，服务执行后再把真实结果交回模型解释。</li>\n      <li><b>Agent / 工作流。</b>一个问题要连续做多步时使用。优先写成步骤清楚、每步可测的工作流。只有任务确实需要临时规划时，再让模型自己决定下一步。</li>\n    </ol>\n    <div class=\"callout warn\">\n      <svg width=\"16\" height=\"16\" viewBox=\"0 0 24 24\" fill=\"none\" stroke=\"currentColor\" stroke-width=\"2\"><path d=\"M12 9v4M12 17h.01\"/><path d=\"M10.3 3.6 1.8 18a2 2 0 0 0 1.7 3h17a2 2 0 0 0 1.7-3L13.7 3.6a2 2 0 0 0-3.4 0z\"/></svg>\n      <span><b>多 Agent 不是默认选项</b>增加角色数量，并不能自动让答案更准。第一版用「一个入口 + 意图路由 + 几种能力模块」就够。等单流程的工具选择、失败重试和状态都稳定了，再考虑多个角色分工。</span>\n    </div>\n  </section>\n\n  <section id=\"s3\">\n    <h2 class=\"sec-title\"><span class=\"num\">03</span>五种实现方式怎么选</h2>\n    <p class=\"sec-desc\">这几种做法可以组合。生产系统常见的是「简单问题直答，文档走检索，数字走工具」。</p>\n\n    <h3>方式 A：直接调用大模型</h3>\n    <p>路径：用户问题 → 提示词模板 → 大模型 → 输出校验 → 答案。适合闲聊、概念解释、文本总结和语言转换。优点是快、便宜、结构简单。它拿不到你的私有数据和此刻的行情，所以回答里要允许模型说明「这是一般性解释」。</p>\n\n    <h3>方式 B：RAG 知识库</h3>\n    <p>路径：文档解析 → 切片 → 向量化 → 检索 → 重排 → 带引用的回答。适合内部文档、投研报告、产品资料和制度。优化时先问「数据找对了没有」，再问「回答是否完整准确」。</p>\n\n    <h3>方式 C：工具调用</h3>\n    <p>路径：用户问题 → 意图识别 → 工具选择 → 模型生成工具参数 → 工具调用 → 返回结果 → 模型解释。适合实时行情、财务指标、选股、回测和业务操作。模型提出的调用只是一份请求，在工具调用成功之前，不能把它写成已经发生的事实。</p>\n\n    <h3>方式 D：结构化数据问答</h3>\n    <p>路径：自然语言 → 结构化条件 → 权限与口径校验 → 服务完成请求 → 结果解释。金融系统优先把用户的话转换成明确条件和固定 API 参数。让模型随意生成请求并直接打到生产库，权限和误查询都很难收住。</p>\n\n    <h3>方式 E：工作流问答</h3>\n    <p>路径：拆任务 → 查行情 → 查财报 → 跑计算 → 校验 → 汇总。适合个股诊断、行业比较、组合分析。计算步骤用确定性服务，模型负责编排说明和解释，不负责数据查找和计算。</p>\n\n    <div class=\"table-wrap\">\n class=\"cards\">\n      <article class=\"card\">\n        <div class=\"k\">接入层</div>\n        <h3>把请求稳稳接进来</h3>\n        <p>API 网关适合普通问答；需要流式输出时用 WebSocket 或 SSE；长任务、回测可以进消息队列，避免用户一直占着连接。</p>\n      </article>\n      <article class=\"card\">\n        <div class=\"k\">核心层</div>\n        <h3>编排、决策、工具、记忆</h3>\n        <p>执行引擎决定下一步。模型网关统一接 DeepSeek、Qwen、GLM 等。工具管理挂行情和选股。记忆只保存理解上下文需要的状态。</p>\n      </article>\n      <article class=\"card\">\n        <div class=\"k\">基础设施</div>\n        <h3>数据按类型落位</h3>\n        <p>向量库存段落，关系库存业务数据，缓存放热点行情，对象存储放研报原件。模型不直接连这些库，由服务代查。</p>\n      </article>\n <li><b>决策：</b>大模型决定是追问、检索、调用工具，还是直接解释。</li>\n      <li><b>记忆：</b>记下已确认的股票、时间和条件。最新价格仍以行情接口为准。</li>\n      <li><b>执行：</b>服务真正调用 API、跑 SQL、跑回测。失败要返回明确错误，而不是让模型编一个数。</li>\n    </ul>\n  </section>\n\n  <section id=\"s-storage\">\n    <h2 class=\"sec-title\"><span class=\"num\">05</span>存储</h2>\n    <p class=\"sec-desc\">问答用到的数据不只有一种放法。向量库、结构化库和知识图谱通常一起用，各管一种找法。</p>\n    <p>很多人一提问答就只想到向量库。实际项目通常是三种存储一起用：向量库找语义相近的段落，结构化库做精确查询，知识图谱表达实体之间的关系。</p>\n    <figure class=\"shot\">\n      <img src=\"/assets/ai-qa/fig-04.png\" alt=\"向量数据库、结构化数据库和知识图谱三种存储及混合使用的示意图\">\n      <figcaption>图：向量库负责「意思相近」，结构化库负责「精确条件」，知识图谱负责「谁和谁有关」。投顾里的股价、财务数字走结构化查询；研报段落走向量或混合检索。</figcaption>\n    </figure>\n    <div class=\"table-wrap\">\n      <table>\n        <caption>三种存储怎么分工 · class=\"sec-title\"><span class=\"num\">06</span>工具调用怎么接</h2>\n    <p class=\"sec-desc\">给模型一个 API 地址，并不等于工具调用完成。模型决策和应用执行要分开。</p>\n\n    <figure class=\"shot\">\n      <img src=\"/assets/ai-qa/fig-05.png\" alt=\"注册工具、模型决策、应用执行、结果回传的四步流程\">\n      <figcaption>图：应用先把工具清单和参数结构交给模型；模型返回工具名和参数；应用去调真实 API；结果再喂回模型。需要别的工具时，循环继续。</figcaption>\n    </figure>\n    <ol class=\"steps\">\n      <li><b>注册工具。</b>每个工具写清用途、参数类型、枚举、默认值和示例。股票代码、日期、指标名不要用含糊的字符串碰运气。</li>\n      <li><b>模型决策。</b>模型输出结构化请求，例如工具名 <b>get_quote</b>、参数 <b>symbol=600519</b>。这一步还没有发生真实查询。</li>\n      <li><b>应用执行。</b>服务做权限、参数和限流检查，再调用行情、数据库或回测代码。空数据、过期数据和错误码要原样保留。</li>\n      <li><b>结果回传。</b>把真实 JSON 交回模型生成解释。若结果不足以回答，就列出缺什么，进入下一轮或向用户追问。</li>\n    </ol>\n\n    <h3>至少检查这六项</h3>\n    <div class=\"table-wrap\">\n      <table>\n        <caption>工具上线前的检查单</caption>\n        <colgroup><col style=\"width:24%\"><col style=\"width:76%\"></colgroup>\n        <thead><tr><th>检查项</th><th>要做到</th></tr></thead>\n        <tbody>\n          <tr><td><b>描述准确</b></td><td>模型能分清「查现价」和「查财务指标」该用哪一个，说明里写使用时机和反例。</td></tr>\n          <tr><td><b>参数规范</b></td><td>日期格式、市场、复权方式、报告期、默认值都有约定，并用 Schema 或 DTO 校验。</td></tr>\n          <tr><td><b>权限正确</b></td><td>用户无权看的数据，工具层就拒绝，不把原始数据交给模型再让它「注意保密」。</td></tr>\n <img src=\"/assets/ai-qa/fig-06.png\" alt=\"函数调用与 MCP 协议的对比：一个决定调什么，一个解决怎么连\">\n      <figcaption>图：函数调用是模型侧能力，负责产出可执行的调用结构；MCP 是应用侧协议，负责用统一方式发现和连接外部工具。二者互补。</figcaption>\n    </figure>\n    <p>函数调用解决「调什么」：模型读懂意图，输出工具名和参数。MCP 解决「怎么连」：宿主应用通过统一协议挂上 GitHub、数据库或其他工具服务器，而不必为每个数据源写一套私有插件格式。投顾系统里的核心行情和回测，建议仍用自己的工具严控参数和权限；MCP 更适合接外部、可替换的工具。</p>\n    <div class=\"callout warn\">\n      <svg 1.7-3L13.7 3.6a2 2 0 0 0-3.4 0z\"/></svg>\n      <span><b>工具并不是越多越好</b>每多一个工具，模型就要多读一段说明，也更容易选错。按意图分组挂载：选股问题只给选股相关工具，知识问题优先走检索。外部 MCP 工具上线前，同样要做权限和审计。</span>\n    </div>\n  </section>\n\n  <section id=\"s6\">\n    <h2 class=\"sec-title\"><span class=\"num\">07</span>记忆和上下文怎么管</h2>\n    <p class=\"sec-desc\">把全部聊天记录无限追加，会又贵又容易跑偏。记忆要分层，上下文要有预算。</p>\n\n    <h3>三层记忆</h3>\n    <figure class=\"shot\">\n      <img src=\"/assets/ai-qa/fig-07.png\" alt=\"短期记忆、工作记忆和长期记忆的三层结构\">\n      <figcaption>图：短期记忆在上下文窗口里，有长度上限；工作记忆是当前任务的待办和变量；长期记忆跨会话保存，通常用向量库做相似检索。</figcaption>\n    </figure>\n    <ul class=\"plain\">\n      <li><b>短期记忆：</b>最近几轮原话、本轮工具记录和中间结果。它占的是模型窗口，所以是第一个瓶颈。</li>\n      <li><b>工作记忆：</b>结构化状态，例如已确认的股票代码、市场、报告期、选股条件、回测是否已跑完。用对象保存，比在长对话里「找它指谁」可靠。</li>\n      <li><b>长期记忆：</b>用户明确授权保存的偏好，或可复用的研究笔记。检索出来后仍要标明时间，不能替代最新行情和授权状态。</li>\n    </ul>\n    <div class=\"callout tip\">\n      <svg width=\"16\" height=\"16\" viewBox=\"0 0 24 24\" fill=\"none\" stroke=\"currentColor\" stroke-width=\"2\"><circle cx=\"12\" cy=\"12\" r=\"9\"/><path d=\"M12 8h.01M11 12h1v4h1\"/></svg>\n      <span><b>对话记忆和业务事实分开</b>历史对话可以帮助理解「它是刚才那只股票」。价格、财务数字、持仓和权限，每次都从对应服务读取。模型记住的一句话，不能认为始终保持不变。</span>\n    </div>\n\n    <h3>窗口里的空间要分配</h3>\n    <figure class=\"shot\">\n      <img src=\"/assets/ai-qa/fig-08.png\" alt=\"以上下文窗口为例的系统提示、工具定义、历史、工具结果和输出预留占比\">\n      <figcaption>图：以较大窗口为例的空间分配示意。工具定义很容易被忽略，接入几十个工具时，光说明就可能占用上万 token。比例不是标准，用来提醒「预算要事先留」。</figcaption>\n    </figure>\n    <p>一次请求里通常挤着五块内容：系统提示（角色和红线）、工具定义、对话历史、工具返回、以及留给这次回答的空间。工具返回的行情表和财报原文最容易把窗口撑满。做法是按意图只挂需要的工具，工具结果先裁剪再送入模型，并给最终回答留出固定额度。</p>\n\n    <h3>上下文太长时，按从轻到重处理</h3>\n    <figure class=\"shot\">\n      <img src=\"/assets/ai-qa/fig-09.png\" alt=\"上下文剪枝、工具结果截断、记忆刷盘和压缩摘要的四层处理\">\n      <figcaption>图：先删掉早期、已无用的工具结果；再对单条过长结果保留开头、结尾和报错；把关键事实写入可靠存储；最后才用模型做摘要压缩。</figcaption>\n    </figure>\n    <ol class=\"steps\">\n      <li><b>剪枝。</b>丢掉早期工具原文，保留系统提示和最近几轮。已经写入工作记忆的股票代码不必在原文里留三份。</li>\n      <li><b>截断单条结果。</b>过长的接口返回保留开头、结尾，并优先留下错误行。报错信息经常在尾部，只留开头会把失败看成成功。</li>\n      <li><b>先落盘再压缩。</b>关键条件、数据时间和工具原文写入日志或状态库，避免摘要把数字写丢。</li>\n      <li><b>再做摘要。</b>用模型把旧消息收成短摘要，明显降低 token。摘要要经过抽查，因为压缩本身也可能改写事实。</li>\n    </ol>\n  </section>\n\n  <section id=\"s7\">\n    <h2 class=\"sec-title\"><span class=\"num\">08</span>调优按什么顺序做</h2>\n    <p class=\"sec-desc\">质量同时受模型、数据、检索、工具、上下文、校验和业务规则影响。没有评测集就改参数，常常只是让手头几个例子变好看。</p>\n\n    <div class=\"callout err\">\n      <svg width=\"16\" height=\"16\" viewBox=\"0 0 24 24\" fill=\"none\" stroke=\"currentColor\" stroke-width=\"2\"><circle cx=\"12\" cy=\"12\" r=\"9\"/><path d=\"M12 8v5M12 16h.01\"/></svg>\n      <span><b>先有对照，再改系统</b>准备一组固定问题，每次只改一个因素：提示词、检索条数、重排、模型或工具说明。记录正确率、延迟和 token。提示词、检索和流程都已经合理，某类任务仍稳定失败时，再考虑微调。</span>\n    </div>\n\n    <h3>第一层：把问题收成结构</h3>\n    <p>典型翻车是：「帮我看看这只股票」却没有代码；「筛选低估值、盈利增长」却没定义指标和周期；追问「那它和上面那只相比」时对不上上下文。</p>\n    <ol class=\"steps\">\n      <li><b>先分意图。</b>例如普通问答、知识库、行情、个股诊断、选股、回测。不同意图走不同模块。</li>\n      <li><b>再收成对象。</b>让模型输出结构化条件，由程序校验，而不是直接生成投资结论。</li>\n      <li><b>缺关键字段就追问。</b>股票代码、日期、指标口径、价格区间缺一不可时，先问再查。</li>\n      <li><b>字段要有类型和枚举。</b>市场、复权、报告期、比较符都限定取值，非法值直接打回。</li>\n    </ol>\n    <div <p>可以按难度路由模型：意图分类和字段抽取用低成本模型；普通解释用通用模型；复杂财报分析用更强的模型。价格、收益、指标和回测始终交给计算服务。比较模型时同时记下答案质量、P50/P95 延迟、token、工具次数、失败率和重试次数。最便宜和最贵都不是默认答案。</p>\n    <div class=\"callout tip\">\n      <svg width=\"16\" 的有效位置</b>减少无关工具说明、截断工具结果、避免重复粘贴历史、让分类任务用小模型。这些都比把温度调来调去更影响账单。温度、提示词和工具定义仍应作为实验变量逐项对比，只是不要同时全改。</span>\n    </div>\n  </section>\n\n  <section id=\"s8\">\n    <h2 class=\"sec-title\"><span class=\"card\">\n        <div class=\"k\">决策质量</div>\n        <h3>工具和步骤选得对不对</h3>\n        <p>该查行情时有没有去查，参数是否合法，有没有多调一串无用工具。目标准确率由业务定，先从当前基线往上抬。</p>\n      </article>\n      <article class=\"card\">\n <p>规则适合判客观项：工具名对不对、参数类型对不对、数字是否来自工具返回、引用段落是否包含结论。模型当裁判适合看相关性和完整性，但要定期抽一批人工复核，避免裁判和被测模型一起偏。</p>\n\n    <h3>题集至少覆盖这些情况</h3>\n    <ul class=\"plain\">\n      <li>普通知识问答，以及必须引用文档的问答。</li>\n      <li>股票代码、市场和时间范围能不能识别出来。</li>\n      <li>选股条件能不能解析成约定字段。</li>\n      <li>工具选择和参数是否正确，回测结果是否按引擎原文解释。</li>\n      <li>数据缺失时是否列出缺项，而不是补一个看起来合理的数。</li>\n      <li>越权访问、恶意输入和不合规请求是否被拒绝或转人工。</li>\n    </ul>\n    <p>起步可以整理 50 到 100 道来自真实咨询的题，每题标注意图、正确资料或正确工具、关键事实和可接受答案要点。之后每次改模型、提示词、检索或流程，都跑同一批，并保留失败样例。</p>\n\n    <div class=\"table-wrap\">\n      <table>\n        <caption>建议一起看的指标 ·
