# Java 做量化回测需要的技术技能

整体分为：**Java 基础技术、数据层、回测引擎核心、量化业务知识、工程化、对接实盘、调试性能优化**几个模块，下面按优先级梳理，同时讲清楚哪些是回测特有，哪些是 Java 工程通用。

## 一、Java 核心编程基础（必备）

1. **Java 基础语法 \&amp; 集合框架**

    - ArrayList、LinkedList、HashMap、TreeMap、ArrayDeque；回测大量 K 线、订单、持仓数据，集合用错直接内存爆炸。

    - 理解 equals/hashCode，对象复用，避免循环里疯狂 new 对象。

2. **Java 8\+ 新特性**

    - Stream、Lambda：批量处理 K 线、因子；

    - LocalDateTime / Instant：时间处理，回测最核心就是时间对齐，**禁止用 Date**。

3. **面向对象、设计模式**

    - 策略模式：不同交易策略；模板模式：回测流程；工厂模式：生成订单；

    - 重点：回测里大量事件驱动，策略和引擎解耦。

4. **IO、文件读写**

    - 读取 csv、parquet 历史行情数据；BufferedReader，NIO，大行情文件不能一次性全加载内存。

5. **异常、日志**

    - SLF4J\+Logback，回测跑几年数据，日志要记录信号、成交、滑点，方便排查 bug。

> 坑点：回测循环跑几十万根 K 线，**不要在循环打印大量 System\.out，会慢几十倍**。
> 
> 

## 二、数据处理能力（回测根基）

### 1\. 行情数据处理

- K 线 \(Tick、1min、5min、日线\) 数据清洗：去重、补缺失、时间对齐、复权处理（前复权 / 后复权）

- 数据结构设计：`Bar`对象（时间、open high low close volume turnover），`Tick`逐笔对象。

- 时间序列处理：按时间窗口滑动，滚动窗口计算（MA、MACD、RSI 等技术指标）。

### 2\. 存储相关

1. **内存存储**

    - 大量历史数据，考虑数组替代集合提升性能；原始类型`double[] long[]`，避免包装类`Double`的开销。

2. **本地文件**

    - CSV、Parquet、Arrow：Parquet 二进制格式适合海量行情，Java 可以用 Apache Parquet 库。

3. **数据库**

    - MySQL：小数据集；**不适合高频回测，查询慢**。

    - ClickHouse / DuckDB：时序行情数据库，Java JDBC 调用，大批量行情查询首选。

    - SQLite：小体量本地回测。

> 常见方案：原始行情存 Parquet/DuckDB，回测时加载到内存做遍历。
> 
> 

## 三、回测引擎核心逻辑（最关键业务）

### 1\. 事件驱动架构（主流回测模式）

回测主流两种模式：

1. **向量化回测**：pandas 那套，Java 做向量化比较麻烦；

2. **事件驱动回测**（Java 首选）：Bar 事件、Tick 事件、订单事件、成交事件、账户事件。

需要自己实现概念：

- **时间轴驱动**：按时间顺序一根一根 K 线推进，模拟真实市场，不能用未来函数！（回测第一大坑）

- **Bar/Tick 推送**：把每根 K 线喂给策略。

- **订单模块**：市价单、限价单；订单状态：新建、部分成交、全部成交、撤单。

- **撮合逻辑**：模拟交易所撮合，滑点、手续费、印花税处理；**这直接决定回测结果是否可信**。

- **账户 \&amp; 持仓模块**：现金、持仓、市值、可用资金，计算净值。

- **策略接口抽象**：统一接口 `onBar(Bar bar)`，不同策略实现这个接口。

### 2\. 回测指标计算

回测结束输出评估指标：

- 净值曲线、累计收益、最大回撤、夏普比率、年化收益率、胜率、盈亏比、交易次数。
需要掌握基础统计学，自己实现指标计算，或引入第三方数学库。

> ⚠️ 致命坑：未来函数，用未来 K 线的数据做当下的交易信号，回测结果虚高，实盘完全失效。
> 
> 

## 四、数学 \&amp; 量化基础

1. 基础统计学：均值、方差、标准差、最大回撤、夏普、波动率。

2. 技术指标实现：MA、EMA、MACD、BOLL、RSI 等，自己手写，或者用第三方库。

3. 理解交易规则：手续费、滑点、涨跌停、T\+1/T\+0、仓位管理。

## 五、第三方 Java 库（不用重复造轮子）

### 数学指标

- **Apache Commons Math**：统计、均值方差。

- **ta4j** ⭐ Java 开源回测框架！最重要，内置指标、事件驱动、回测评估。

> 如果不想从零写引擎，直接基于 ta4j 开发；如果要自研引擎可以参考 ta4j 源码。
> 
> 

### 数据文件

- Apache Parquet：读取二进制行情

- OpenCSV：读取 csv 行情

- DuckDB JDBC：嵌入式分析数据库

### 工具

- Guava：集合工具

- FastJSON2 / Jackson：序列化回测报告

## 六、性能优化技能（Java 回测重中之重）

回测经常跑数年、几十万根 K 线，性能差跑一次几分钟甚至几小时。

1. JVM 调优：堆内存设置 `-Xmx`，避免 Full GC；

2. 减少对象创建：循环内避免 new 对象，对象池，使用原始类型数组，减少 GC；

3. 避免装箱拆箱；

4. 内存溢出处理：超大数据集不要全部加载内存，支持分段流式读取；

5. 可以用 JProfiler / Arthas 分析 GC、热点方法。

## 七、工程与输出

1. 回测报告输出：输出 csv 净值，导出图表；Java 绘图可以使用 JFreeChart，或者导出数据到 Python 绘图。

2. 参数遍历：网格搜索，遍历不同参数批量回测。

3. Maven/Gradle 项目管理，单元测试 JUnit：对撮合、账户逻辑写单元测试，引擎逻辑必须测试，否则回测 bug 很难发现。

## 八、拓展：对接实盘（回测之后）

如果回测之后要对接券商 API：

- HTTP/WebSocket，Netty；解析行情推送，下单接口。

# 两种路线总结

### 路线 A：基于开源框架二次开发（快速上手，推荐新手）

使用 **TA4J**，你只需要：
Java 基础、数据读取、写策略逻辑、理解回测概念，不用从零写撮合、账户、指标。

### 路线 B：从零自研 Java 回测引擎

需要掌握全部上面技能：事件驱动、撮合引擎、账户持仓、数据层、性能调优。自由度高，适合定制化需求。

# 学习顺序建议

1. Java 基础 \+ Java8 时间、集合

2. 学习 TA4J，跑通 demo 策略，理解事件驱动回测的流程

3. 准备一份历史 K 线数据，做数据读取清洗

4. 看懂 ta4j 内部：Bar、Strategy、TradingSession、Account

5. 手写简单简化版回测引擎，理解撮合、滑点、账户

6. JVM 性能调优，处理大数据量回测

7. 实现回测评估指标，生成回测报告

## 常见踩坑提醒

1. 时间时区问题，行情时间要统一时区；

2. 复权数据，不复权回测股票结果完全错误；

3. 滑点、手续费忘记加，回测收益虚高；

4. 未来函数；

5. 大量循环创建对象，GC 疯狂卡顿；
