## 1. 结论

**指标和信号预计算使用 ta4j 0.16**（`pom.xml` 的 `ta4j-core`）。`SignalPrepCache` 把 `CompactSeries` 转成 `BarSeries`（`DoubleNum`），由实现了 `Ta4jBuyPreparer` / `Ta4jSellPreparer` 的规则填买卖标记，然后丢掉 `BarSeries`。日频撮合仍是 `PortfolioEngine`，不调用 `BarSeriesManager`。

绩效仍是 `PortfolioAnalytics`，没有使用 ta4j 的 `Criteria`。全市场向量扫描 `VectorSmaCrossEngine` 仍直接调用 `SmaSignals`。单票上的 `signal()` 也保留 `SmaSignals`，供未走预计算的路径使用。

新增技术指标：实现规则接口和对应的 `Ta4j*Preparer`，注册进 `TradeSignalCatalog`。

曾经存在一条**单票 ta4j 回测**，已经删除。`docs/BACKTEST_FLOW.md` 写明产品页统一走组合回测。现在用的是同一份 `ta4j-core` 0.16，只负责指标和交叉规则，不负责下单。

下面「能力地图」和示例都按 **0.16 这个 jar 的公开 API** 核对过。更高版本（0.18 起拆模块，并补了夏普等指标）类名和包名会变，不要直接套。

## 2. 现有引擎对应 ta4j 的哪一层

ta4j 的 `BarSeriesManager` 一次只跑**一根** `BarSeries`（一只股票或一个指数）。本项目要的是多标的共用现金、T+1、涨跌停、停牌、印花税、行业持仓上限。这些不在 ta4j 0.16 的执行模型里，所以组合引擎是自己写的。

| 本项目 | 类 | ta4j 0.16 里最接近的东西 | 差别 |
|--------|----|--------------------------|------|
| 日 K | `CompactSeries`（`double[]`） | `Bar` + `BarSeries` | 预计算时 `Ta4jBars` 转成 `DoubleNum` 序列，算完即丢；撮合循环只读原始数组 |
| 均线 / 金叉 / 死叉 | `SmaGoldenBuyRule` / `MaDeathSellRule` | `SMAIndicator` + `CrossedUpIndicatorRule` / `CrossedDownIndicatorRule` | 预计算走 ta4j。金叉仍是「前一根短 ≤ 长，当根短 > 长」，且从长周期下标起读，避免半窗误触发 |
| 顶背离、动量排序 | `MaTopDivSellRule` / `UniverseRankBuyRule` | `HighestValueIndicator`；动量用 `ClosePriceIndicator` 的 `今/昨-1` | 不用 `ROCIndicator`（0.16 的 ROC 常按百分比）。顶背离窗口是 `shortMa+1` |
| 买卖规则注册 | `TradeSignalCatalog` | `Rule` 组合进 `BaseStrategy` | 新指标实现规则接口和 `Ta4jBuyPreparer` / `Ta4jSellPreparer` 后注册。撮合不持有 `BaseStrategy` |
| 撮合 | `PortfolioEngine` | `BarSeriesManager` + `TradeExecutionModel` | 默认 `TradeOnCurrentCloseModel` 在**信号当根收盘**成交。`TradeOnNextOpenModel` 才接近本项目的次日开盘 |
| 费用 | `CostModel`（佣金、滑点、卖出印花税分开） | `LinearTransactionCostModel(rate)` | ta4j 是单一比例，买卖同一个费率，没有印花税 |
| 交易约束 | `MarketRules`（停牌、涨停不可买、跌停不可卖、T+1） | 无 | 要自己包一层，不能指望 `BarSeriesManager` |
| 绩效 | `PortfolioAnalytics` | `org.ta4j.core.criteria.*` | 0.16 **没有** `SharpeRatioCriterion`。最大回撤、盈亏比、胜/负笔数有现成类 |

内置且能提交组合回测的信号（预计算走 ta4j，注册在 `TradeSignalCatalog`）：

- 买入：`SMA_GOLDEN` 双均线金叉，`UNIVERSE_RANK` 成分按动量排序
- 卖出：`MA_DEATH` 死叉、`MA_TOP_DIV` 顶背离仍走 ta4j 预计算。`HOLD_PERIOD` 不预计算，只按持股天数卖。RSI、BOLL、KDJ、MACD、阴线、均线条件在 `IndicatorSellRule`，用收盘和开盘一次写成 `boolean[]`，不建 `BarSeries`。默认卖出仍是 `MA_DEATH`

榜单上的 17 个策略（`ProductSeed`，S001–S017）是展示种子，没有 ta4j 策略对象，也不能整包丢进 `BarSeriesManager`。

## 3. ta4j 0.16 能力地图

服务已依赖这一份（`pom.xml`）。独立练习用同一版本，避免和运行路径的类名对不上：

```xml
<dependency>
  <groupId>org.ta4j</groupId>
  <artifactId>ta4j-core</artifactId>
  <version>0.16</version>
</dependency>
```

### 3.1 行情

- `Bar`：一根 K 线的时间、OHLC、量。
- `BaseBarSeriesBuilder` → `BarSeries`：按时间**严格递增**追加。日线用 `series.addBar(endTime, open, high, low, close, volume)`，`endTime` 用 `ZonedDateTime`。
- `Num`：默认 `DecimalNum`。热路径想少分配，可 `withNumTypeOf(DoubleNum.class)`。精度和 `double` 手写不完全一致，对账时要留容差。

### 3.2 指标

包：`org.ta4j.core.indicators`。

先掌握这些，足够覆盖本项目现在的均线，并往下扩展：

| 类 | 用途 |
|----|------|
| `ClosePriceIndicator` | 收盘价序列，几乎所有指标的输入 |
| `SMAIndicator` / `EMAIndicator` | 简单 / 指数均线 |
| `MACDIndicator` | MACD 差离值 |
| `RSIIndicator` | RSI |

指标按 bar 下标 `getValue(index)` 取值，结果会被缓存。`getUnstableBars()` 表示前若干根还没攒满窗口，策略里要用 `BaseStrategy` 的 `unstableBars` 挡住，否则开头会发出假信号。

### 3.3 规则

包：`org.ta4j.core.rules`。规则只回答「这一根满不满足」，不负责下单。

和本项目最相关的：

- `CrossedUpIndicatorRule` / `CrossedDownIndicatorRule`：短均线上穿 / 下穿长均线，对应金叉、死叉。
- `OverIndicatorRule` / `UnderIndicatorRule`：站上 / 跌破。
- `StopLossRule` / `StopGainRule` / `TrailingStopLossRule`：止损止盈。本项目没有这三类。
- `OpenedPositionMinimumBarCountRule`：持仓至少 N 根才允许卖，接近 `HOLD_PERIOD`，但是按 bar 数而不是交易日规则。
- `AndRule` / `OrRule` / `NotRule`：组合条件。

`isSatisfied(index, tradingRecord)` 的 `index` 只能使用该下标及更早的 bar。用未来下标就是未来函数。

### 3.4 策略与跑回测

- `BaseStrategy(name, entryRule, exitRule, unstableBars)`
- `BarSeriesManager` 在 `org.ta4j.core.backtest`（不在 `org.ta4j.core` 根包）

```text
new BarSeriesManager(series)                              // 当根收盘成交
new BarSeriesManager(series, new TradeOnNextOpenModel())  // 下一根开盘成交
new BarSeriesManager(series, txCost, holdingCost, model)  // 再加成本
manager.run(strategy) → TradingRecord
```

`TradingRecord` 里是一串 `Position`（一进一出）。`getPositions()` 看已闭合回合，`getCurrentPosition()` 看还没平的仓。

默认执行模型是 `TradeOnCurrentCloseModel`：信号出现在这根 K 线的收盘价上，并以**同一根收盘价**成交。这和本项目「昨收出信号、次日开盘成交」不一致。要对齐口径，必须传入 `TradeOnNextOpenModel`。它仍然不知道涨跌停、停牌、T+1 和多标的资金竞争。

### 3.5 成本

`org.ta4j.core.analysis.cost`：

- `ZeroCostModel`：不计费
- `LinearTransactionCostModel(rate)`：成交额 × 单一费率（佣金和滑点只能折成一个数）
- `LinearBorrowingCostModel`：持仓融资成本，A 股现货用不上
- `FixedTransactionCostModel`：固定金额

卖出印花税、买入不收印花税，要在成交价或数量上自己改，或者不要用 ta4j 的成本模型、沿用本项目 `CostModel`。

### 3.6 绩效（0.16 实际有的类）

`org.ta4j.core.criteria` 与 `criteria.pnl`。和本项目结果页能对上的：

| 本项目口径 | ta4j 0.16 |
|------------|-----------|
| 最大回撤 | `MaximumDrawdownCriterion` |
| 收益 / 回撤 | `ReturnOverMaxDrawdownCriterion` |
| 盈亏比 | `ProfitLossRatioCriterion` |
| 盈利笔数 / 亏损笔数 | `NumberOfWinningPositionsCriterion` / `NumberOfLosingPositionsCriterion` |
| 总盈亏 | `ProfitLossCriterion`、`ReturnCriterion` |
| 相对买入持有 | `VersusEnterAndHoldCriterion`、`EnterAndHoldReturnCriterion` |
| Sharpe | **没有这个类**。本项目在 `PortfolioAnalytics.sharpeFromEquity`：日收益均值 / 总体标准差 × √252，无风险利率 0 |
| 换手 | **没有**。本项目是双边成交额 / (初始资金 × 交易日)，是近似密度 |

`AnalysisCriterion.calculate(series, tradingRecord)` 返回 `Num`。`betterThan` 用来做参数比较，不是给前端展示的。

0.16 也没有投资组合账户、没有订单簿、没有涨跌停。

## 4. 系统掌握的顺序

每一阶段都用**同一只股票、同一段日 K** 做，最后和 `SmaSignals` 对账。不要一上来改 `PortfolioEngine`。

### 阶段 1：把 K 线装进 BarSeries

从镜像或 `CompactSeries` 取出 open/high/low/close/volume，转成 `ZonedDateTime`（时区固定 `Asia/Shanghai`，用收盘时刻，例如 15:00）。断言时间递增、没有重复交易日。

验收：`series.getBarCount()` 等于交易日数，`getBar(i).getClosePrice()` 与原始收盘一致。

### 阶段 2：只算指标，不交易

`ClosePriceIndicator` 上套 `SMAIndicator(close, 20)` 与 `SMAIndicator(close, 60)`。从下标 `60` 起，把 `sma.getValue(i)` 和 `SmaSignals.sma(closeArray, i, n)` 比较，允许 `1e-8` 相对误差（`DecimalNum` 与 `double` 的差别）。

验收：能指出前 59 根是不稳定区。

### 阶段 3：规则与策略

```text
entry = CrossedUpIndicatorRule(sma20, sma60)
exit  = CrossedDownIndicatorRule(sma20, sma60)
strategy = BaseStrategy("sma", entry, exit, 60)
```

在每个下标上调用 `strategy.shouldEnter(i)` / `shouldExit(i)`，与 `SmaSignals.goldenCross` / `deathCross` 的布尔值对齐。`unstableBars` 必须 ≥ 长均线周期，否则前段会多出交叉。

验收：金叉、死叉的下标集合一致。这是接回本项目前唯一值得做的对照。

### 阶段 4：执行模型

同一策略分别用默认 `BarSeriesManager` 和 `TradeOnNextOpenModel` 跑。数 `TradingRecord.getPositionCount()`，并打印每笔 `Position` 的进场价。

验收：能讲清默认是当根收盘价，`TradeOnNextOpenModel` 是下一根开盘价。后者才接近 `PortfolioEngine`。

### 阶段 5：成本与绩效

加上 `LinearTransactionCostModel(0.0003)` 表示佣金。再用 `MaximumDrawdownCriterion`、`ProfitLossRatioCriterion`、`NumberOfWinningPositionsCriterion` 算三个数。

夏普不要从 0.16 里找。若要和本项目比，把 ta4j 的权益曲线导出来，套 `PortfolioAnalytics.sharpeFromEquity` 的同一公式（总体方差、√252、rf=0）。两套最大回撤定义也可能差在「用收盘权益还是用持仓市值」，对不上时先写明口径再改公式。

### 阶段 6：新指标接到现有预计算

适合用 ta4j 的：

- 新的技术指标和交叉、阈值类信号。实现 `BuySignalRule` 或 `SellSignalRule`，再实现 `Ta4jBuyPreparer` / `Ta4jSellPreparer`，在 `TradeSignalCatalog.builtins()` 注册
- 单票对照测试：同一段 `double[]` 上，ta4j 标记要和手写公式的布尔值一致

不适合用 ta4j 替换的：

- `PortfolioEngine` 的多标的资金、仓位上限、同行业上限
- `MarketRules` 的停牌和涨跌停
- 买卖不对称的印花税
- 策略榜单 `gn_*` 展示数据（那是种子净值，不是回测记录）

`BarSeries` 只在第一次预计算时按股票各建一次，结果写入 `PreparedSignals` 的布尔数组后丢弃。日循环不要再读 ta4j 对象。1500 只 × 500 根的第一次计算会因为 `Bar` / `Num` 分配变慢，第二次命中缓存后只剩撮合。

## 5. 最小示例（独立练习，0.16）

下面这段能编译运行。它不读取数据库，也不改产品服务。成交选在下一根开盘，和组合引擎的时点一致；费用只有一笔比例佣金。

```java
import org.ta4j.core.BarSeries;
import org.ta4j.core.BaseBarSeriesBuilder;
import org.ta4j.core.BaseStrategy;
import org.ta4j.core.Rule;
import org.ta4j.core.Strategy;
import org.ta4j.core.TradingRecord;
import org.ta4j.core.analysis.cost.LinearTransactionCostModel;
import org.ta4j.core.analysis.cost.ZeroCostModel;
import org.ta4j.core.backtest.BarSeriesManager;
import org.ta4j.core.backtest.TradeOnNextOpenModel;
import org.ta4j.core.criteria.MaximumDrawdownCriterion;
import org.ta4j.core.criteria.pnl.ProfitLossRatioCriterion;
import org.ta4j.core.indicators.SMAIndicator;
import org.ta4j.core.indicators.helpers.ClosePriceIndicator;
import org.ta4j.core.rules.CrossedDownIndicatorRule;
import org.ta4j.core.rules.CrossedUpIndicatorRule;

import java.time.Duration;
import java.time.LocalDate;
import java.time.ZoneId;
import java.time.ZonedDateTime;

public final class Ta4jSmaOnce {
    public static void main(String[] args) {
        ZoneId sh = ZoneId.of("Asia/Shanghai");
        BarSeries series = new BaseBarSeriesBuilder().withName("demo").build();
        LocalDate d = LocalDate.of(2024, 1, 2);
        double price = 10;
        for (int i = 0; i < 120; i++) {
            price += Math.sin(i / 8.0);
            ZonedDateTime end = d.plusDays(i).atTime(15, 0).atZone(sh);
            series.addBar(Duration.ofDays(1), end, price, price + 0.2, price - 0.2, price, 1_000);
        }

        ClosePriceIndicator close = new ClosePriceIndicator(series);
        SMAIndicator fast = new SMAIndicator(close, 5);
        SMAIndicator slow = new SMAIndicator(close, 20);
        Rule entry = new CrossedUpIndicatorRule(fast, slow);
        Rule exit = new CrossedDownIndicatorRule(fast, slow);
        Strategy strategy = new BaseStrategy("sma-5-20", entry, exit, 20);

        BarSeriesManager manager = new BarSeriesManager(
                series,
                new LinearTransactionCostModel(0.0003),
                new ZeroCostModel(),
                new TradeOnNextOpenModel());
        TradingRecord record = manager.run(strategy);

        System.out.println("positions=" + record.getPositionCount());
        System.out.println("mdd=" + new MaximumDrawdownCriterion().calculate(series, record));
        System.out.println("plRatio=" + new ProfitLossRatioCriterion().calculate(series, record));
    }
}
```

跑通之后，把正弦价格换成一只真实股票的收盘价，用阶段 3 的方法对齐 `SmaSignals`。正弦序列只证明 API 通，不能当作策略收益。

## 6. 掌握清单

- 能从日 K 建 `BarSeries`，时区固定，时间递增。
- 能用 `SMAIndicator` 复现 `SmaSignals.sma`，并说明不稳定区。
- 能说出 `CrossedUpIndicatorRule` 与 `SmaSignals.goldenCross` 的对应关系。
- 能改用 `TradeOnNextOpenModel`，并解释默认模型为何会和本项目成交价不同。
- 能用 `MaximumDrawdownCriterion`、`ProfitLossRatioCriterion` 读结果，并知道 0.16 没有夏普。
- 能说明多标的、T+1、涨跌停、印花税仍然留在 `PortfolioEngine` / `CostModel` / `MarketRules`。
